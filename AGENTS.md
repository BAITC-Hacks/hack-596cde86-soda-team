# AGENTS.md — «Аким на 5 часов»

Инструкции для ИИ-агентов (Codex и др.), работающих в этом репозитории. Читай целиком перед любой задачей.

## 1. Что это за проект

AI-симулятор управления городом. Пользователь получает бюджет 100 условных единиц и данные по 5 районам Астаны, выбирает ровно 5 мероприятий из каталога (14 шт.), получает **Astana Quality of Life Score** и объяснение от ИИ-агента: сильные стороны, риски, компромиссы, как улучшить набор.

Главный принцип: **все числа считает детерминированный движок `engine/`. LLM никогда не считает и не придумывает числа** — она только вызывает инструменты движка и пересказывает их результат.

Оценка проекта идёт по коду и GitHub-репозиторию (демо и презентации нет). Поэтому важны: работоспособность, архитектура, README, воспроизводимость, тесты, чистая история коммитов.

## 2. Стек

- Backend: Python 3.11, FastAPI, Pydantic v2, pytest
- AI: OpenAI API с tool calling; модель задаётся через `OPENAI_MODEL` в `.env`
- Frontend: React + TypeScript + Vite, Recharts для графиков
- Запуск: `docker compose up` (обязательно работает с нуля)

## 5. Правила валидации (validator.py)

Набор невалиден, если нарушено любое правило. Валидатор возвращает **все** нарушения с понятной причиной на русском, Score не считается.

1. Сумма стоимостей ≤ 100. Остаток не даёт бонуса.
2. Ровно 5 мер.
3. Без повторов мер.
4. Для `district` район обязателен и должен существовать; для `city` район не указывается.
5. Не более 2 мер из одного направления.
6. Несовместимости из раздела 4 запрещены.
7. Порядок мер не важен.

Трактовка: следуем правилам датасета — 2 меры из одного направления допустимы (как в примере из ТЗ, распределение 2/1/1/1). Зафиксировано в README.

## 6. Формула Score (score.py, simulation.py)

Горизонт H = 8 кварталов.

1. Новое значение показателя района d по показателю k:
   `I'[d][k] = clip(I[d][k] + Σ effect[m][k] × (8 − L[m]) / 8 + синергии, 0, 100)`
   Синергии добавляются до clip, без масштабирования лагом.
2. Оценка района: `D[d] = Σ w[k] × I'[d][k]`
3. Городской балл: `D_avg = Σ pop[d] × D[d]`
4. `N_crit` = число пар (район, показатель) со значением **строго < 40** после всех эффектов.
5. `Score = 0.7 × D_avg + 0.3 × min(D[d]) − 1.0 × N_crit`

Движок считает без округлений; округление только при выводе (2 знака).

## 8. Интерфейс движка

Публичные функции `engine/` (сигнатуры не менять без согласования):

```python
validate(selection: list[Choice]) -> ValidationResult          # ok + список ошибок
simulate(selection: list[Choice]) -> SimulationResult          # показатели до/после по районам, D, D_avg, N_crit, Score
contributions(selection: list[Choice]) -> list[Contribution]   # вклад меры = Score(набор) − Score(набор без меры)
compare(a: list[Choice], b: list[Choice]) -> Comparison
find_best(top_n: int = 5) -> list[RankedSelection]             # полный перебор, кешировать результат
suggest_swaps(selection: list[Choice]) -> list[Swap]           # замены одной меры/района, дающие рост Score
```

`Choice = {measure_id: str, district: str | None}`

## 9. API (api/main.py)

- `GET  /api/data` — районы, показатели, каталог, веса, бюджет
- `POST /api/validate` — проверка набора (можно вызывать на каждое изменение в UI)
- `POST /api/simulate` — полный расчёт
- `POST /api/explain` — объяснение от агента по набору
- `GET  /api/best` — топ наборов из оптимизатора
- `GET  /api/health`

Ошибки валидации — HTTP 422 с телом `{errors: [{rule, message}]}`.

## 10. ИИ-агент (ai/)

- Агент получает набор пользователя и имеет доступ к инструментам из раздела 8 через tool calling.
- Агент обязан: объяснить итоговый Score, сильные стороны, риски, компромиссы, последствия для слабого района (Нура), сравнить с оптимумом и предложить конкретные замены.
- **Любое число в ответе агента должно прийти из результата инструмента.** Запрещено вычислять или оценивать числа самостоятельно. Это правило прописано в системном промпте.
- Промпты лежат в `ai/prompts/*.md`, не строками в коде.
- **Fallback без ключа:** если `OPENAI_API_KEY` не задан или API недоступно, `ai/fallback.py` собирает объяснение по шаблону из результатов движка. Проект должен полностью работать без ключа — проверяющий может его не иметь.
- Таймаут и обработка ошибок API обязательны.

## 11. Frontend

- Выбор 5 мер, выбор района для `district`-мер, живой счётчик бюджета и направлений.
- Ошибки валидации показываются до отправки; кнопка расчёта неактивна при невалидном наборе.
- Результат: Score, прирост к базе (52.56), разница с оптимумом, изменения показателей по районам (график/тепловая карта), критические значения < 40 выделены.
- Блок объяснения агента.
- Все данные — только через API, ничего не хардкодить.
